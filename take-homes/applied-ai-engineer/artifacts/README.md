# Artifacts — committed run evidence

Every file here is generated by one command and committed, so the claims in
[`../WRITEUP.md`](../WRITEUP.md) can be checked without running anything:

```bash
python -m tools.make_artifacts     # regenerates this entire directory
```

No API key is used or needed. See [Provenance](#provenance) for exactly which
numbers come from authored fixtures and which from a rule-based baseline —
that distinction matters and is not blurred anywhere.

## Files

### `pipeline_run.json` — full-corpus coverage
A single run over all 140 transcripts. Contains the run summary, every one of
the 22 proposed actions in full (title, type, priority, priority rationale,
verbatim cited snippets, de-dup reasoning, near-misses considered and
rejected), the de-duplication table, the cross-call cluster table, the drop
distribution across 10 distinct reason codes, and a **per-call disposition
list for all 140 calls** so any individual call can be audited rather than
taken on trust.

### `idempotency.json` — re-run safety, measured at the outbox
`run → approve → apply → forced re-run → apply`. The forced re-run is the real
test: `force=True` re-extracts and re-gates every transcript from scratch, so
all 213 candidates and all 22 actions are rebuilt, and the ledger suppresses
every one. Outbox line counts are recorded before and after; the delta is
zero. Also records the cheap path (unchanged content hash → 134 transcripts
skipped, 0 work done).

### `partial_failure.json` — one bad transcript doesn't poison the run
`call-070.md` is replaced with a copy containing a dialogue line that has no
speaker tag. Result: 1 errored, 139 completed, the run still proposes actions,
and the failure is isolated to its own ledger row for retry. Generating this
artifact **found a real bug** — see the Overrides section of the write-up.

### `eval.json` — dev-set score with an explicit pass/fail definition
Carries the pass/fail definition in full, the threshold, the label mapping,
per-case expected-vs-actual action sets, the 7 deterministic traps, and 5-run
pass rates bucketed into stable-pass / flaky / stable-fail plus mean pairwise
Jaccard over the proposed action sets. Also states how a genuine miss is
distinguished from a wrong grader: expected and actual sets are both printed
per call and no judge model is involved.

### `adversarial_gates.json` — the gates, not the prompt, are the defence
A deliberately hostile model returns a hallucinated turn citation, a candidate
sourced from an `[INTERNAL]` speaker, a candidate whose only evidence is the
call-005 injection text, and out-of-vocabulary enums. Each is blocked by a
different gate; none reaches the write path.

### `review_digest.md` — what the human reviewer actually sees
The generated review queue: 22 cards, needs-attention first, then by priority.
Each card leads with the verbatim customer quote and a `transcript:line` link,
then the priority rule that fired by name, then the de-duplication decision
including rejected near-misses, then the full ticket body behind a collapsed
`<details>`. Approve/reject commands are on every card.

### `run_log.jsonl` + `run_summary.json` + `observability_index.json`
The structured event stream from the full-corpus run — one event per decision
with `run_id`, `call_id`, `stage`, a closed-enum `reason`, `fingerprint`,
`prompt_version` and `model`. `observability_index.json` aggregates it and
documents the specific greps that distinguish a silent stop from a silent
mis-filing from a hallucinated citation.

## Provenance

Two providers, kept strictly separate because conflating them would overstate
the result in both directions:

| Provider | Covers | Used for | Fidelity |
|---|---|---|---|
| `replay` | calls 001–015 | **the dev-set eval** (`eval.json`) | Hand-authored from the transcripts, including all the noise — retracted gripes, hearsay, cosmetic nitpicks, injection attempts |
| `heuristic` | all 140 | full-corpus plumbing (`pipeline_run.json`, `idempotency.json`, `partial_failure.json`) | Keyword rules. Poor precision by design |
| `chain` | all 140 | the artifact runs | Fixtures where they exist, heuristic elsewhere |

**What the full-corpus numbers prove:** all 140 transcripts parse, screen,
gate, de-duplicate, cluster and land in the ledger; a second run writes
nothing; one failure is contained. These are properties of the deterministic
machinery, which is what the heuristic baseline exercises.

**What they do not prove:** extraction quality on the 125 holdout calls. The
heuristic provider is not a model and is never scored against the labels. The
149 `unactionable_vague` drops in the full-corpus run are mostly the baseline
firing on surface cues and then being correctly filtered — a real model would
produce far fewer candidates and more of them would survive. The honest
reading is that **extraction quality on the holdout is unmeasured**; every
layer downstream of extraction is measured and passing.
